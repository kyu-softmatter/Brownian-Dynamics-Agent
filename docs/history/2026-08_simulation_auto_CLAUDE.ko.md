**L5 는 새 레이어가 아니라 이미 있던 것을 정정한 것입니다** (2026-08-05). `bdbot/run.py`의
`@RUN.builder("케이스이름")` 레지스트리 + `Build` dataclass가 정확히 mater_plan.md의 L5
설계(`build(spec) -> ...`)이고, `execute()`가 L6(실행 루프)+L7(저장)을 겸합니다.
`chain-bend-2d-oscill`·`trap-drag-2d-hex300`·**`trap-2d-5um`**(2026-08-05 이관·재실행 대조)이
이미 이 계약을 씁니다. `trap-2d-5um`은 자체 `HarmonicTrap` 클래스를 `bdbot.traps.make_trap`
으로 바꾸고 재실행해 옛 런(`a49f2508556b`·`d724e8d507cc`)과 관측량 5종을 표시 정밀도까지
대조했습니다 — 완전히 일치합니다(같은 시드 20260803, 같은 물리라 궤적이 그대로 재현됨).
이관 중 버그 둘을 잡았습니다(KB `tooling` 2건): ① `MET.build(extra=...)`는 `m.update(extra)`
로 병합해서 `finalize()`의 `result`가 `metrics["extra"]["result"]`가 아니라 **최상위**
`metrics["result"]`에 온다 — 아니면 조용히 nan. ② `sample()`이 표본마다 전체 N입자 배열을
그대로 돌려주면 `observables.npz`가 448KB→148MB(330배)로 부푼다 — 파생량은 클로저에서
누적하고 원시배열은 필요한 부분집합만 채워야 한다.

**`abp-rod-2d-run-flip`도 이관·재실행 대조 완료** (2026-08-05). 이 계는 페어 상호작용도
트랩도 없어서(활성힘은 비보존력) `pe_per_particle`이 가리킬 퍼텐셜 에너지가 없습니다 —
대신 원래 구현이 이미 평형 지표로 썼던 `⟨cos Δθ⟩`(직전 호출 대비 방향 상관)을 씁니다:
정상이면 매 호출 다른 노이즈 실현이라 절대 정확히 상수가 안 되고, 회전확산이 죽으면
정확히 1.0에 고정돼 FROZEN이 잡힙니다. 재실행 결과가 옛 런(N=1000, `74fb2d81066a`)의
관측량 5종과 표시 정밀도까지 일치합니다. 세 케이스 모두 이관 중 같은 종류의 구멍이
있었습니다 — **spec.params/numerics에 build()가 필요로 하는 값(seed·L_star·Dr_star 등)이
빠져 있으면 build(spec)이 케이스 YAML을 다시 읽을 수 없어 값을 못 구합니다** (KB
`tooling` 항목). 셋 다 추가해서 run_id가 바뀌었지만(물리 해시 필드라서) 기존 런은
그대로 남습니다.

**`soft-r3-2d-A-sweep`도 이관·재실행 대조 완료** (2026-08-05). 전체 크기(A=100, N=400,

**새 케이스를 시작할 때** — 도구가 절차를 강제합니다:
```bash
$PY -m bdbot.cli status                      # 어디서 막혀 있는지
$PY -m bdbot.cli intake init  intake/<case>  # 템플릿 → 이미지 읽고 채움 (skill bd-intake)
$PY -m bdbot.cli intake check intake/<case>  # FAIL / BLOCKED / READY
$PY -m bdbot.cli system check intake/<case>  # tier · derived_from · 유도값 재계산
$PY -m bdbot.cli nondim spec  <case>         # L3 → specs/<run_id>.json  (실행 안 함)
$PY -m bdbot.cli nondim show  <run_id>       # 스펙만 보고 재현 + 해시 검증 ← 사람 확인 #3
$PY -m bdbot.cli health --gate specs/<run_id>.json   # L4 실행 전 게이트
$PY -m bdbot.cli health runs/<run_id>                # L4 수치 건전성 판정
```

**L3 산출물은 `specs/<run_id>.json` 하나입니다** ([`bdbot/nondim.py`](../../bdbot/nondim.py)).
L2와 L4 사이의 **유일한 계약**이고, L4는 케이스 코드를 임포트하지 않고 이것만 읽습니다.
자족성의 판정은 `nondim show` — 스펙만으로 리포트가 다 그려지면 자족적입니다.
스펙은 네 가지를 스스로 검사합니다 (물리 검사인 `checks`와 **다른 층**입니다):
원장 완전성(필수 역할 4종) · 무차원수가 정말 원장 두 항목의 비인가 · 기준이 원장에 있는가 ·
역변환 앵커가 성립하는가. 적대적 검사는 `scratch/verify_nondim_guards.py` (33/33).
공통 코드는 [`bdbot/`](../../bdbot/__init__.py) (모듈 20개). 케이스 스크립트는 **고유 물리만** 씁니다 —
[`cases/soft_r3_2d.py`](../../cases/soft_r3_2d.py)를 본으로 삼으세요.
**`BLOCKED`는 실패가 아닙니다** — 무엇이 없는지 하나로 특정했다는 뜻이고, 지어내서
READY로 만들면 안 됩니다 (규칙 3).

**`bdbot/`에 무엇을 올릴지는 "두 번 나왔는가"로만 판단합니다.** 세 번째 케이스에서
또 나오면 그때 올립니다. 지금 일부러 남겨둔 것: 평형 판정 지표 · 관측량 · 검증 전략 ·
지배 시간척도 선택 · 초기 배치 · 표본 수집 루프 (skill `bd-physics` §6.3).

리팩터 후에는 반드시 `$PY scratch/verify_1c_equivalence.py` 로 결과 불변을 확인합니다.

**`run_id`는 물리 필드만 해시합니다** ([`bdbot/runid.py`](../../bdbot/runid.py) `DOC_KEYS`). 주석·출처·유도값을
고쳐도 런이 무효화되지 않아야 합니다 — 예전에 `derived_from` 필드를 추가한 것만으로 1-A의
run_id가 바뀐 적이 있습니다. **반대 방향도 똑같이 위험합니다**: 1-B 스펙에는 물리계가 아예
없어서 `d` 5µm→0.5µm·`η` 62배로 바꿔도(τ_B 16.1배 차이) run_id가 **같았고**, 완료된 다른 계의
런으로 오인돼 예전 결과가 새 계의 결과로 보고됐습니다. 해시는 **물리를 정하는 것 전부**를

**`trap-drag` L4 결과 — 7속도 × 시드 9 = 63런 재실행으로 정정 (2026-08-06)** ⭐️
`runs/trap-drag-2d-hex300__ENSEMBLE/vsweep_ensemble.{png,json}` ·
`scratch/trap_drag_vsweep.py`. **모든 오차가 실현 간 산포(앙상블 SEM)입니다** —
예전 값들은 속도마다 단일 런의 블록 SEM 을 썼습니다.

| 무엇 | 옛 값 (단일 런·블록SEM) | **새 값 (시드 9·앙상블SEM)** |
|---|---|---|
| 항복력 `F(v→0)` | 35~45 kT/d, 0에서 11~20σ | **34~41 kT/d, 9.5~12.6σ** — 크기는 유지, 유의도 하향 |
| 전단 담화 `F/γv` | 16.9 → 1.87 | **16.8 → 1.84** (9.2배) — 재현 |
| **결함 수** | **v 무관** (6.8~9.4) | ⛔ **v 의존성 있음** (최대−최소 = 5.2·SEM) |
| **회복률** | −0.5 → 67% **단조 증가** | ⛔ **비단조**, −13% → 최대 36%(γv=72.6) 후 감소 |

⛔ **뒤집힌 것 둘**: ① 결함 수는 v 에 무관하지 않습니다 — γv≈24 에서 **9.43 로 정점**이고
양끝(2.42·1549)에서 6.8~7.0 으로 떨어지는 **비단조 봉우리**입니다. "임계 속도 없음"은
유지되지만 "v 무관"은 아닙니다. ② 회복률 67% 는 한 실현의 값이고 앙상블 평균은 36% 가
최대입니다. **둘 다 단일 런 + 과소평가된 오차 때문에 잘못 읽은 것입니다.**

⚠️ **블록 SEM 과소평가 배수는 관측량·속도마다 다릅니다.** 널리 인용된 **2.35×** 는
`ΔU/입자` 값이고, 같은 런에서 `F_drag` 는 **1.37×** 였습니다 — 섞어 쓰면 안 됩니다.
v-스윕 전체에서 `F_drag` 는 **1.09~2.28×** (중앙 1.63)이고 **속도가 클수록 커집니다**
(저속 1.1 → 고속 2.28). 확률적 결함을 만드는 계에서 시드 앙상블 없이 오차를 인용하면
과신합니다.

   한다(이미 이 파일에 적힌 결론). `chain-bend-2d-dlvo`는 반대 방향에서 같은
   원칙을 적용한 것이다 — [P1][P2]가 쓴 굽힘강성 `κ_θ=EI/ℓ`(연속체 빔이론이라는
   일반 관계식)을 그대로 갖다 쓰지 않고, 비드 사이에 실제로 작용하는 **DLVO 중심
   페어힘 하나**만으로 사슬을 만들어 굽힘이 나오는지를 직접 실행으로 봤다.
   `abp-rod`의 이방성 병진 마찰도 이 규칙이 왜 있는지를 보여준다 — BD에는 입자간
   유체역학 상호작용(HI)이 없어 등방 평균 마찰 γ̄만 쓸 수 있고, 그 결과 이방성은
   **일반 공식으로도 못 흉내낸다** (BD로는 불가 — mater_plan §20 질문 10).

## 작업 관행

- **케이스 주도**: 프레임워크를 먼저 만들지 않는다. 케이스 하나를 끝까지 관통하고,
  두 번 나온 것만 추상화한다 (mater_plan.md §16 Phase 1).
- **함께 검증**: 스케일 표와 무차원화 결과는 사람과 같이 본다. 지식이 쌓이기 전까지는
  물리 판단을 혼자 확정하지 않는다.
- **런이 없어도 배운 것은 남긴다.** 스케치 해석·문헌 증류·도구 교훈은 런에 붙지 않으므로
  `record.json`에 자리가 없다 → `kb/entries/`에 넣는다:
  ```bash
  $PY tools/kb.py add --origin intake --kind pitfall --source "파일#앵커" --claim "..."
  ```
  `origin`: `intake`(스케치 해석) · `paper`(논문) · `tooling`(도구) · `method` ·
  `handbook`(**책·참고서** — 증류본은 `docs/books/` 에 두고 엔트리의 `source` 를 `증류본#절 ← [약칭] p.쪽`
  으로 적어 되짚을 수 있게 한다)
- **관측량마다 역할(`role`)을 정한다.** 기본값은 `measurement`(판정 안 함)이다.
  `implementation_check` 만 불일치가 FAIL이고, `hypothesis` 불일치는 **결과로 보고**한다.
- **결과는 그래프와 애니메이션으로 보여준다.** ⭐️ 말과 표만으로 보고하지 않는다 —
  기본값은 **둘 다 만들어 첨부하는 것**이다 (mater_plan.md §13.3).
  - **그래프**: 측정 vs 예측을 같은 축에. 검사 문턱·해석해·문헌값을 선으로 겹친다.
    "무엇이 틀렸는지"가 눈에 보여야 한다 — [`scratch/viz_chain_bend.py`](../../verify/viz_chain_bend.py)
    6패널이 본보기다 (스펙 오류 5건이 패널 하나씩에 대응).
  - **애니메이션**: 계가 실제로 어떻게 움직이는지. `kT=0`(모드 형태)과 `kT>0`(열요동에
    묻히는 정도)을 **나란히** 두면 SNR 문제가 숫자보다 빨리 보인다.
    애니메이션은 큰 `dt`로 싸게 만들어도 되지만 **생산 측정이 아님을 반드시 명시**한다.
  - ⚠️ **그래프 라벨은 한글이 아니라 영어로 쓴다.** matplotlib 기본 `DejaVu Sans`에는 한글이
    없어 라벨이 전부 `□`가 되는데, 한글을 갖춘 폰트(`AppleGothic`·`Apple SD Gothic Neo`·
    `NanumGothic`)는 반대로 `−`(U+2212)·`ŷ`(U+0177) 같은 기호가 빠져 있다(실측) — 폰트
    전환으로 고치려 하지 말고 **애초에 축·범례·타이틀·주석을 전부 영어로** 쓴다.
    이 분야 물리·통계 용어는 애초에 한국어 표현이 어색하거나 안 익은 경우가 많고
    (예: `de-correlation time`·`shear thinning`·`yield force`), 영어 쪽이 뜻을 더
    정확하고 간결하게 전달한다 — 폰트 문제가 없더라도 유지할 규칙이다.
    생성 후 `missing from font` 경고가 0인지 확인한다.
- **런이 끝나면 반드시 사후분석을 돌린다.** 성공/실패를 선언하지 말고 측정으로 판정한다:
