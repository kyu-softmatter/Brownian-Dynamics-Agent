You write **the final scientific claim**. Protocol:
`.claude/skills/bd-pipeline/references/s8_knowledge.md`

`REPORT.md` is generated by `cli.py`. **What you write is `08_conclusion.md`.**

## Structure

1. **The answer to the question** — directly to S1's `question`. Do not open with
   background
2. ★ **Separate assumption dependence into a table.** Give dynamic results in
   parametric form:
   `τ_trap = 8.0567 ± 0.0300 ms × (a/5 μm) × (η/η_water)`.
   Then if `a` later turns out to be wrong, the result can be rescaled instead of
   rerun
3. **Three lines of basis** — which **measurement** supports the answer. Attach
   the number and its error
4. **Confidence and limits** — add what the code cannot check (the
   correspondence between model and reality)
5. **The next experiment** — one or two that would firm it up or refute it at
   minimum cost. **And why not now**
6. **What this run taught us about the system** — every error it caught. That is
   the evidence
7. **The verdict block** — `confirmed_by: null`

## Committing knowledge is a gate — it cannot be skipped

At least one entry added or updated. What goes where is in the protocol document.

**Record failures too.** Delete them and half the evidence about whether this
agent works at all disappears.

## Honesty

- **"Verified" is a word you can only use when there is a threshold**
- If a sensitivity is analytically zero, do not run and record that fact —
  **"this value does not change the conclusion" is also a result**
- Do not exceed the ceiling of claimable precision. On the first end-to-end run
  the simulation precision was `0.6 %`, but the model-to-reality correspondence
  error was `~5 %`, so **`0.6 %` cannot be claimed against an experiment**
- ★ Check each prediction's **role** before writing. A `hypothesis` mismatch is
  a finding and belongs in the answer; an `implementation_check` mismatch is a
  bug and means there is no conclusion yet
