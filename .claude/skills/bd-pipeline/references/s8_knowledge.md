# S8 — conclusion and the knowledge commit

> **`REPORT.md` is generated by the CLI.** What you write is the conclusion
> document — the answer to the question, the causal hypotheses, the next
> experiment, and **the knowledge entries**.

## 1. Structure of the conclusion document

Format example:
[`08_conclusion.md`](../../../../runs_s1s8/2026-07-28_trap-2d-5um_2dfb9d/08_conclusion.md)

### ① The answer to the question — one paragraph

Answer S1's `question` **directly**. Do not open with background.

★ **Separate assumption dependence into a table.** The first end-to-end run did
this:

| Quantity | Settled value | Assumption dependence |
|---|---|---|
| `⟨x²⟩` | `416.58 ± 1.85 nm²` | **none** — fixed by `k` and `T` alone |
| `τ_trap` | `8.0567 ± 0.0300 ms` `× (a/5 μm) × (η/η_water)` | linear in `a` and `η` |

**Writing a dynamic result in parametric form stops the assumption from
hiding.** If `a` later turns out to be wrong, that table alone lets you rescale
instead of re-running.

### ② Three lines of basis

Which **measurement** supports the answer. Attach the number and its error.
Not "theory says so" but "this run produced this value."

### ③ Confidence and limits — as a table

Cite `REPORT.md`'s gate table, but **add the limits the code cannot check**:

- the correspondence between model and reality (no hydrodynamic interactions,
  constant-`γ` Stokes, the tails of uniform noise)
- finite `N` and finite `t`
- the influence of the assumptions (the sensitivity result)

★ **If a sensitivity is analytically zero, do not run it.** On the first
end-to-end run `∂ln⟨x²⟩/∂lnη = 0` exactly, so the one-at-a-time sensitivity run
was skipped and that fact was recorded. **"This value does not change the
conclusion" is also a result.**

★ **Do not exceed the ceiling of claimable precision.** On that run the
simulation precision was `0.6 %` but the model-to-reality correspondence error
was `~5 %`, so `0.6 %` cannot be claimed against an experiment.

### ④ Proposed next experiment

One or two minimum-cost experiments that would **firm up or refute** this
conclusion. State what each buys and what it costs. And **why not now** (low
priority / no measurement available / the user deferred it).

### ⑤ What this run taught us about the system

**Record every error it caught.** There were four on the first end-to-end run:
three found by tests, one found by digging into "a FAIL came out — why?" This
section is the evidence about whether this agent works at all.

### ⑥ The verdict block

```yaml
verdict_overall: PASS_WITH_INCONCLUSIVE
proposed_by: agent
confirmed_by: null            # ← awaiting human confirmation
```

## 2. The knowledge commit — **cannot be skipped** (a gate)

Contract: [`knowledge/wiki/CLAUDE.md`](../../../../knowledge/wiki/CLAUDE.md)

### What goes where

| What happened | Where it goes |
|---|---|
| you answered the question | `wiki/findings/<slug>.md` |
| you could not answer it | `wiki/questions/<slug>.md` (`status: open`) — **left open, never deleted** |
| an approach failed | `wiki/findings/dead-end-<slug>.md` |
| a system was handled for the first time | `wiki/systems/<system>--<dynamics>.md` |
| a literature verification value was extracted | `wiki/benchmarks/<id>.md` |
| a parameter gained a basis | `wiki/concepts/<slug>.md` |
| a card's benchmark was confirmed | promote that card's benchmark to `[O]` and record the measured value |
| a tool bit you | `tools/kb.py add --origin tooling --kind pitfall` |

### The frontmatter is a contract

```yaml
---
type: finding
author: agent
drafted: 2026-07-28
confirmed_by:                 # leave empty. A human fills it after review
status: proposed
question: "…?"                # one sentence
answer: "…"                   # one sentence. If there is none, it goes to questions/
cause_class: analysis         # if this finding is a failure case
runs: [<run_id>]
cites: [file paths]
---
```

### The findings format — the diagnostic path is the point

```markdown
## Symptom      exactly what was observed. No "it looked wrong" -> "KS p-value was 0.0000 in all four conditions"
## Diagnostic path   what you suspected and how you eliminated it. **In order.** Next time this
                symptom appears, someone follows this order — that is this document's central value
## Root cause   one paragraph. Consistent with cause_class
## Prescription a concrete diff. No "be careful"
## Prevention   the test, guard or document you added. **If none, write "none" explicitly** —
                a recurring "none" is the signal to build a guard
```

### Discipline — break it and the wiki becomes a rumour store

- **Contradicting an existing entry means a new entry plus `supersedes`.** Never
  silently overwrite
- **Do not cite `reproduced: no` as a basis.** Mark it `[source, not reproduced]`
- **Promotion from `finding` to `concept` needs human approval.** This stops an
  agent inflating its own observations into concepts
- **Leave `confirmed_by` empty**

### Benchmark promotion

A reproducible number goes into `tests/`:

```python
@pytest.mark.benchmark
def test_...():
    """Take the tolerance from the **theoretical statistical error** (tailoring it
    to the observed value is post-hoc rationalization)."""
```

When comparing against a documented value, **take the tolerance from the
significant figures printed in the document** — a single global constant lets the
loose case excuse the strict one.

## 3. Progress record — append-only

- Update the status document. **Before the code, not after.**
- Do not edit a past row; add a new one marked `correction:`
- Do not delete a superseded section; mark it `⚠️ retired` — **if the refuted
  original disappears, the refutation stops being readable**

## 4. Gates

- at least one knowledge entry added or updated
- `REPORT.md` is self-contained, including figure and value links
- the "confidence and limits" section **cites** the sensitivity result
- `confirmed_by: null` is still there
- every prediction's `role` was checked before the conclusion was written — a
  `hypothesis` mismatch belongs in the answer, an `implementation_check`
  mismatch means there is no conclusion yet
